# Repository navigation and contribution conventions

GitHub recognizes a root `README.md` as the landing page and `README.md` files in folders as contextual indexes. Prefer descriptive lowercase directory names and relative Markdown links. Keep product and business work distinct.

## Filing rules

1. Start at the root index; each major directory has its own README.
2. Add new business candidates under `business/<slug>/` with status and ownership.
3. Record decisions with dates and evidence links; do not imply unexecuted work was completed.
4. Use Issues for actionable work, Discussions for longer design dialogue, and pull requests for reviewed changes.
5. Before **any** GitHub repository test, publish a pre-test entry explaining Timothy's discussion, problem, hypothesis, solution, method, expected results, and falsification conditions. Afterward report actual observations, interpretations, deviations, failures, evidence, limits, and next steps in the same thread.
6. Never modify the `echo-upstream-mirror` branch for experiments. Preserve charter boundaries.

## Review checklist

Ensure relative links resolve, statuses are accurate, no credentials or private materials are included, and changes remain within the approved scope. This checklist is documentation, not a claim that tests have run.
